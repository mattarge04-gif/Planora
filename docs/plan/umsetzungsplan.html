Bis zur fertigen App bei Siemens, in Modulen

Modell B2B, eine Instanz pro Kunde (E34–E37): Jeder Kunde bekommt einen eigenen Server mit eigener App, als Docker-Compose-Paket, gehostet von uns in der Schweiz oder On-Premise beim Kunden. Eine Codebasis; jedes Kundenfeature wird ein Modul mit Schalter. Externe Abhängigkeit nur die Claude API, alles andere Open Source und selbst gehostet. Die „Demo“ ist die vollständig funktionierende App beim ersten Kunden. Lieferung in Stufen: jede Stufe ist eine lauffähige Version. Annahme: Matt Vollzeit ≈ 5 PT/Woche [A], bei Halbzeit verdoppeln sich alle Wochen. Woche 1 = Start nach Freigabe M0.

Wo du Hilfe von aussen brauchst

Nach Dringlichkeit sortiert. Nur was Agenten nicht ersetzen können. Sätze: IT CHF 130–180/h, Security CHF 200–400/h [A], vor Vergabe Offerten einholen.

Aufgaben für den Chef

  • W1–W2: Bei Siemens die IT-Freigabe anstossen (Security-Fragebogen, Hosting bei uns oder On-Premise, ev. Pentest-Pflicht). Das dauert erfahrungsgemäss Wochen bis Monate [A] und liegt nicht in Matts Hand.
  • W1–W4: Bauteil-Katalog fachlich prüfen: welche 30–50 Typen braucht es zuerst?
  • W2–W10: Lebensdauer-Standardtabelle pro Bauteiltyp. Wird für Stufe 2 gebraucht.
  • Bis W12: echte TGA-Unterlagen von Siemens. Ohne sie ist die KI-Erfassung (Stufe 4) nicht prüfbar.
  • Bis W14: mit Jurist klären, ob Siemens die Claude API (Anthropic, Datenfluss ausserhalb CH) akzeptiert; sonst bleibt KI bei Siemens ausgeschaltet.
  • Laufend: Vertrag pro Kunde inkl. „sein“ Feature (wird Modul im Produkt), Vertretung und Support für Matt regeln.

Was den Plan verschieben kann

  • IT-Freigabe bei Siemens. Die App kann fertig sein, bevor sie auf deren Server darf. Früh anstossen, On-Premise-Anforderungen früh kennen.
  • Viele Instanzen = viele Updates. Jede Instanz muss Updates und Datenbank-Migrationen sicher bekommen. Update-Ablauf und Backup pro Instanz sind Teil von M1, nicht später.
  • 3D auf schwachen Firmen-Laptops. Leistungsstufen normal/schwach/2D aus Spike S3b, Messung auf echtem Siemens-Gerät früh machen.
  • Kundenfeature sprengt den Plan. Jedes Feature wird separat geschätzt und bezahlt, kommt als Modul nach Stufe 2 und verschiebt den Rest sichtbar.
  • Matt fällt aus. Ein Entwickler ist der grösste Engpass. Codex prüft laufend, Doku und Spec machen den Code für eine Vertretung lesbar.
Gestrichen bis nach der Demo (kommt bei Bedarf als Kundenmodul): Mandantentrennung mit RLS, Keycloak + Microsoft-SSO, Exoscale-Managed-Dienste, AWS Bedrock, öffentliche APIs aus E32 (geo.admin/GWR, Nager.Date, Pwned Passwords), Raumerkennung aus Grundriss (ersetzt durch Interview/Formular), FR/IT, Tolgee, GlitchTip, Uptime Kuma, cosign, Renovate, OWASP ZAP.
